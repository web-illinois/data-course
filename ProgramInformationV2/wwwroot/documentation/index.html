Program Information Documentation

Introduction

The Program Information application is where colleges, departments, and units maintain the information that appears on their public websites about programs, credentials, courses, sections, and requirement sets. This documentation is written for the people who edit that information. It explains each screen, what each field is for, and what happens when you save, transfer, or delete.

Key concept: sources

A source is a separate workspace for one college, department, or unit. Each source has its own data, filters, note templates, settings, security, and API key.

Updating one source does not affect any other source. Always confirm which source you are working in before making changes, especially before deleting.

How the information fits together

Program
  └── Credential            (degree, certificate, or endorsement)
		└── Requirement Set (0 to many per credential)
			  └── Course    (0 to many per requirement set)
					└── Section (term-based class)
  • A program groups one or more credentials.
  • A credential can contain 0 to many requirement sets.
  • A requirement set can contain 0 to many courses. It describes a rule such as "must take all of these courses", "must take one of these courses", or "must take 9 credit hours from the following courses".
  • A course has one or more sections.

Documentation summary

Folder What it covers
Program Editing a program: general information, links and images, overview, admissions, quote, filters, credential list, related links, notes, technical information, security, and audit history.
Credential Editing a credential: general information, filters, course list (requirement sets), transcript information, technical information, security, and audit history.
Requirement Set Creating requirement sets (groups of courses needed for a credential), writing the rule in the Description field, setting credit hours, adding courses, shared and private sets, and how credentials, requirement sets, and courses connect.
Course Editing a course: general information, faculty, location and time, section list, importing courses from the Electronic Data Warehouse, Canvas, and Coursera.
Section Editing a section: general information, location and time, faculty, and technical information.
Transfer Saving data to JSON files and loading them back, to copy data between sources, back up before large changes, or make bulk edits in a text editor.
Configuration Source-level setup: sources, filters, note templates, security and API keys, settings, deleting a source, and testing access.
FieldsUsed Turning features on or off for your source, hiding fields you do not use, and adding instructions for each field.
Audit Reports for reviewing changes and checking data quality, such as unused requirement sets and the course import log.

Where to start

  • New to the application? Read this page, then the Configuration and FieldsUsed overviews. or Course.
  • Building a plan of study? Read Requirement Set.
  • Making a backup or bulk change? Read Transfer.
  • Checking for problems? Read Audit.

Conventions used

  • Bold text is a button, field, or menu item as it appears on screen.
  • Routes such as /program/general show the page address within the application.
  • Most pages have a Save button. Changes are not stored until you select it. Security pages are the exception and save immediately.
  • Fields and pages may differ between sources because features can be turned on or off, and fields hidden, in Fields Used.

Getting help

Contact IT Partners @ Education for questions about changes that are not shown in the audit pages or for problems not covered here.
